`NodeDownloader` es la implementación por defecto de `DownloaderInterface` utilizada por todos los retrievers. Usa el `fetch` global de Node.js y escribe cada archivo de forma atómica mediante un archivo temporal (`.tmp`) que se renombra al destino final solo cuando la descarga concluye correctamente.

## Uso básico

Si no pasas un descargador al crear un retriever, se instancia `new NodeDownloader()` automáticamente con sus valores por defecto. También puedes usarlo de forma independiente o inyectarlo con opciones personalizadas:

```ts [scripts/custom-downloader.ts]
import { NodeDownloader, XsdRetriever } from '@nodecfdi/xml-resource-retriever';

const downloader = new NodeDownloader({
  timeoutMs: 15_000,
  maxBytes: 10 * 1024 * 1024, // 10 MiB
  headers: {
    'User-Agent': 'nodecfdi-app/1.0',
  },
});

const retriever = new XsdRetriever('./storage', downloader);
```

También puedes reemplazar el descargador en una instancia ya creada:

```ts
retriever.setDownloader(downloader);
```

## Opciones de configuración

`NodeDownloaderOptions` extiende la interfaz estándar [`RequestInit`](https://developer.mozilla.org/en-US/docs/Web/API/RequestInit) de `fetch` y añade dos opciones específicas:

| Opción | Tipo | Valor por defecto | Descripción |
| --- | --- | --- | --- |
| `timeoutMs` | `number` | `30_000` (30 s) | Tiempo máximo en milisegundos para la petición y la descarga del cuerpo. Usa `0` para desactivar el timeout. |
| `maxBytes` | `number` | `52_428_800` (50 MiB) | Tamaño máximo permitido de la respuesta en bytes (validado en `Content-Length` y durante el stream). Usa `0` para desactivar el límite. |
| `...requestInit` | `RequestInit` | `undefined` | Cualquier opción compatible con `fetch` (`headers`, `signal`, `redirect`, etc.). |

::warning
Si pasas un valor negativo, `NaN` o `Infinity` en `timeoutMs` o `maxBytes`, el constructor lanza un `RangeError` inmediatamente.
::

### Combinación de `timeoutMs` y `signal`

Si proporcionas tu propio `AbortSignal` en `options.signal` junto con un `timeoutMs > 0`, `NodeDownloader` combina ambas señales usando `AbortSignal.any(...)`. La descarga se abortará con la primera señal que se dispare.

```ts
const controller = new AbortController();
const downloader = new NodeDownloader({
  timeoutMs: 20_000,
  signal: controller.signal,
});
```

## Escritura atómica y limpieza

Durante `downloadTo(source, destination)`:

1. Valida que `source` utilice protocolo `http:` o `https:`.
2. Ejecuta `fetch` y vuelve a validar el protocolo de `response.url` en caso de redirecciones.
3. Escribe el flujo en `${destination}.${uuid}.tmp` aplicando el límite de bytes si `maxBytes > 0`.
4. Al finalizar sin errores, renombra el archivo temporal a `destination`.

Si la descarga falla o se cancela a mitad del proceso, el archivo temporal se elimina automáticamente y cualquier archivo previo en `destination` permanece intacto.

## Manejo de errores

Cualquier fallo durante `downloadTo(source, destination)` (error de red, código HTTP distinto de `2xx`, timeout, protocolo no permitido o exceso de `maxBytes`) se envuelve en un `AggregateError` con el mensaje `Unable to download <source> to <destination>`.

```ts
import { NodeDownloader } from '@nodecfdi/xml-resource-retriever';

const downloader = new NodeDownloader({ timeoutMs: 5_000 });

try {
  await downloader.downloadTo('https://example.com/schema.xsd', './schema.xsd');
} catch (error) {
  if (error instanceof AggregateError) {
    console.error(error.message);
    console.error('Causa original:', error.errors[0]);
  }
}
```
