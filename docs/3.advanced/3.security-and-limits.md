Al descargar archivos remotos y seguir enlaces declarados dentro de documentos XML de terceros, existen riesgos de seguridad y consumo excesivo de recursos. `@nodecfdi/xml-resource-retriever` aplica varias defensas activas por defecto.

## Restricción de protocolos HTTP y HTTPS

Tanto [`NodeDownloader`](/packages/xml-resource-retriever/usage/node-downloader) como `buildPath()` solo aceptan los esquemas `http:` y `https:`.

- Esquemas como `file:`, `data:`, `ftp:` o `javascript:` son rechazados antes de ejecutar `fetch`.
- Si un servidor responde con una redirección hacia un protocolo no permitido, `NodeDownloader` valida `response.url` después de la petición y aborta la operación.

## Prevención de *path traversal*

`buildPath(url)` (implementado sobre [`resolveLocalFilePath`](/packages/xml-resource-retriever/api-reference/utilities)) protege el directorio base contra escrituras fuera de su alcance:

- Rechaza URLs que contengan bytes nulos (`\0` o `%00`).
- Resuelve la ruta absoluta final y verifica con `path.relative()` que permanezca estrictamente dentro de `basePath` (rechaza secuencias `..` que escapen del directorio raíz).
- `download(url)` rechaza además URLs cuya ruta local termine en `/`.

## Validación de archivos XML

Después de descargar un archivo, `AbstractXmlRetriever` ejecuta `validateDownloadedXmlFile(source, localPath)`:

1. **Archivo vacío**: si `size === 0`, elimina el archivo y lanza un error.
2. **Tipo MIME**: detecta el tipo real mediante *magic bytes* (`file-type`) y, si no aplica (archivos de texto plano), recurre a la extensión (`mime`). Solo acepta `application/xml`, tipos terminados en `+xml` o tipos `text/*`. Si no coincide (por ejemplo, `application/gzip` o `application/json`), elimina el archivo y lanza un error.
3. **Parseo XML**: al leer el documento en `retrieve()`, elimina un posible BOM UTF-8 (`\uFEFF`) y parsea el contenido con `@nodecfdi/cfdi-core`. Si el XML está mal formado o carece de `documentElement`, elimina el archivo local y lanza un error con la causa original (`{ cause: error }`).

## Límites operativos por defecto

| Protección | Valor por defecto | Dónde se configura |
| --- | --- | --- |
| Profundidad de recursión | `50` niveles | `AbstractXmlRetriever.maxDepth()` |
| Máximo de recursos por `retrieve()` | `500` archivos | `AbstractXmlRetriever.maxResources()` |
| Descargas concurrentes | `6` simultáneas | `AbstractXmlRetriever.maxConcurrentDownloads()` |
| Timeout por descarga | `30_000` ms (30 s) | `NodeDownloader({ timeoutMs })` |
| Tamaño máximo por respuesta | `52_428_800` bytes (50 MiB) | `NodeDownloader({ maxBytes })` |

## Protección contra ciclos infinitos

Antes de descargar un recurso en `retrieve()`, `AbstractXmlRetriever` registra inmediatamente su URL en el historial interno. Si un archivo se referencia a sí mismo o existe una dependencia circular (`A -> B -> A`), la segunda referencia reutiliza la ruta ya registrada en el historial sin volver a descargar ni entrar en recursión infinita.

::note
Si el límite de tamaño se supera durante la lectura de una respuesta *chunked* (sin encabezado `Content-Length`), `NodeDownloader` corta el stream mediante `createByteLimitTransform`, borra el archivo `.tmp` y preserva intacto cualquier archivo previo en el destino.
::
