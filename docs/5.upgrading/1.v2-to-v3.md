La versión `3.0.0` moderniza `@nodecfdi/xml-resource-retriever` para aprovechar APIs nativas de Node.js (`fetch`, `AbortSignal.timeout`, `node:fs/promises`), adopta ESM puro, introduce descargas concurrentes y endurece las validaciones de seguridad.

## Resumen de cambios rompientes

### 1. Node.js `^22.13.0 || ^24 || ^26` y ESM puro

- **Requisitos de Node.js**: el soporte mínimo sube de Node `16/18` a `^22.13.0 || ^24 || ^26`.
- **Fin de CommonJS**: se elimina el build dual (`require()` / `./dist/commonjs`). El paquete ahora es **ESM puro** (`"type": "module"`).

::code-group
```cjs [Antes (v2.x - CJS)]
const { XsdRetriever } = require('@nodecfdi/xml-resource-retriever');
```

```ts [Después (v3.0.0 - ESM)]
import { XsdRetriever } from '@nodecfdi/xml-resource-retriever';
```
::

### 2. `@nodecfdi/cfdi-core` ahora es dependencia directa

En `v2.x`, `@nodecfdi/cfdi-core` (`>=0.6.2`) era una `peerDependency` que debías instalar manualmente. En `v3.0.0` pasa a ser una dependencia directa (`^2.0.0`). Si solo tenías `@nodecfdi/cfdi-core` en tu `package.json` por requerimiento de este paquete, puedes retirarlo.

### 3. `NodeDownloader` migrado a `fetch` nativo

`NodeDownloader` dejó de usar `node:http` / `node:https` y ahora usa el `fetch` global de Node.js:

- **Eliminación de `adapterFor(inputUrl)`**: si extendías `NodeDownloader` sobrescribiendo el método protegido `adapterFor`, migra a pasar [`NodeDownloaderOptions`](/packages/xml-resource-retriever/usage/node-downloader) (que extiende `RequestInit`) o implementa [`DownloaderInterface`](/packages/xml-resource-retriever/advanced/custom-downloaders).
- **Límites activos por defecto**:
  - `timeoutMs`: `30_000` ms (usa `0` para desactivar).
  - `maxBytes`: `52_428_800` bytes / 50 MiB (usa `0` para desactivar).
- **Errores HTTP en `AggregateError`**: ante una respuesta HTTP fallida (`!response.ok`), `error.errors[0]` ahora es una instancia de `Error` (con `response.statusText || "HTTP <status>"`) en lugar de un `string`.
- **Escritura atómica**: las descargas se escriben en un archivo temporal `.tmp` y se renombran al finalizar, evitando sobrescribir o corromper archivos previos si ocurre un error.

```ts [Ajustar timeout o tamaño máximo]
import { NodeDownloader, XsdRetriever } from '@nodecfdi/xml-resource-retriever';

const downloader = new NodeDownloader({
  timeoutMs: 60_000,
  maxBytes: 0, // sin límite de tamaño
});

const retriever = new XsdRetriever('./storage', downloader);
```

### 4. Descargas concurrentes y límites en `AbstractXmlRetriever`

`AbstractXmlRetriever` ahora descarga dependencias hermanas en paralelo y aplica límites por defecto para evitar recursión infinita o agotamiento de recursos:

- `maxDepth()` = `50`
- `maxResources()` = `500`
- `maxConcurrentDownloads()` = `6`

::warning
Si utilizas una implementación personalizada de `DownloaderInterface`, verifica que soporte múltiples llamadas simultáneas a `downloadTo()`. Si necesitas forzar descargas estrictamente secuenciales, sobrescribe `maxConcurrentDownloads()` retornando `1` en una subclase.
::

### 5. Validaciones estrictas y cambios en `AbstractBaseRetriever`

- **`buildPath(url)` y `download(url)`**: rechazan intentos de *path traversal* (`..`), bytes nulos (`\0`, `%00`) y rutas locales terminadas en `/`.
- **`retrieveHistory()`**: ahora devuelve una copia plana nueva (`Object.fromEntries(...)`) en lugar de una referencia al objeto interno; mutar el resultado ya no afecta el estado del retriever.
- **Métodos protegidos**:
  - `urlParts(url)` devuelve `UrlParts | undefined` (antes `Record<string, string> | undefined`).
  - Nuevos helpers protegidos disponibles para subclases: `hasInHistory(source)`, `getFromHistory(source)` y `historySize()`.

## Lista de verificación

::steps
### Actualiza tu versión de Node.js y módulos

Asegúrate de ejecutar en Node.js `>=22.13.0` y usar `import` (ESM) en lugar de `require()`.

### Actualiza la dependencia

```bash
pnpm add @nodecfdi/xml-resource-retriever@^3.0.0
```

### Revisa usos avanzados de `NodeDownloader` y subclases

- Si sobrescribías `NodeDownloader.adapterFor()`, reemplázalo por `NodeDownloaderOptions` o una clase que implemente `DownloaderInterface`.
- Si capturabas `AggregateError` asumiendo que `error.errors[0]` era un `string`, lee `error.errors[0].message` cuando sea instancia de `Error`.
- Si tu árbol XML supera 50 niveles o 500 archivos, sobrescribe `maxDepth()` o `maxResources()` en tu [retriever personalizado](/packages/xml-resource-retriever/advanced/custom-retrievers).
::
